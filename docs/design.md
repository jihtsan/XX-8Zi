| 项目 | 内容 |

## 2. 风格判断

参考图可以理解为数字粗野主义的近邻，但不是典型的纯数字粗野主义。更准确的描述是：

> **玄秘工业档案（Mystic Techno-Utilitarianism）**
>
> 以工业科技、实用主义平面设计和复古未来主义为骨架，用矿物档案、珠串轨道和东方留白替代军工语义。

参考图包含以下风格成分：

- **科技实用主义（Techno-utilitarian）**：编号、标签、状态、坐标、设备铭牌式排版。
- **工业复古未来主义（Industrial retro-futurism）**：对未来技术的复古想象，带有实验室、航天和工业系统气质。
- **编辑式粗野主义（Editorial brutalism）**：黑白高反差、超大文字、硬边框和直接的信息层级。
- **模块化品牌系统**：字标、徽章、几何图案、数据条和说明文字可以自由组合。

它与典型数字粗野主义的区别在于：参考图并不粗糙或随意，而是经过精细控制的字体、间距和标志系统。项目对外沟通时可简称“数字粗野主义”，内部设计与实现统一使用“玄秘工业档案”作为方向名称。

## 3. 设计目标

1. 让水晶、佛珠及相关饰品呈现为值得观察和收藏的“矿物标本”，而不是普通货架商品。
2. 建立现代、克制、神秘且可信的品牌感，避免廉价玄学、古风模板或过度赛博朋克。
3. 让商品实拍成为页面中最主要的色彩来源，界面本身保持黑白和低饱和。
4. 保证浏览、登录、立即购买和订单状态清晰，视觉实验不能妨碍交易路径。
5. 商城前台与管理后台共享设计语言，但根据任务采用不同的信息密度。

## 4. 核心视觉概念

### 4.1 矿物档案

把每件商品视为一份可被查阅的矿物或珠串档案：

- 商品编号写作 `CRYSTAL-001`、`BEADS-012` 等展示性编号。
- 商品类别可以使用“矿物系列”“木质系列”“佛珠系列”等中文名称。
- 珠径、手围、材质和规格使用字段化排版，不伪装成真实检测报告。
- 商品详情可以使用“材质档案”“规格记录”“影像记录”等标题。
- 后台和订单仍使用 PRD 定义的正式业务名称，不用视觉概念替换领域术语。

### 4.2 珠串轨道

参考图中的圆点、轨道和重复几何可以转换为：

- 一串连续圆点组成的分隔线。
- 同心圆、环形轨道和珠径刻度。
- 四向星、晶体切面和放射状几何。
- 由圆点或方格构成的低密度底纹。

这些图形只承担品牌识别和分区作用，不表达算命结果、能量等级或未经证实的功效。

### 4.3 可取与不可取

| 从参考图提取 | 在本项目中避免 |
| --- | --- |
| 黑白高对比和大字号标题 | 美国国旗、军事徽章和国家机构语义 |
| 等宽数字、编号和数据标签 | “任务”“作战”“权限等级”等军工文案 |
| 硬边框、标签条和模块化组合 | 大面积故障、闪烁或难以阅读的 Glitch 效果 |
| 圆点、轨道、晶格和扫描线 | 每个区域都堆满装饰与英文字符 |
| 少量衬线字体形成神秘感 | 古风卷轴、金色祥云和常见玄学模板 |
| 产品图与界面形成强烈反差 | 虚构鉴定、疗效、转运或命理承诺 |

## 5. 设计原则

### 5.1 商品先于装饰

商品图片是视觉中心。装饰图形不得覆盖珠串主体、影响材质颜色判断或抢占“立即购买”的注意力。

### 5.2 信息像档案，操作像商城

标题、规格和编号可以具有档案感；按钮、表单、错误提示和订单状态必须符合常规 Web 使用习惯。客户不需要学习新的交互方式。

### 5.3 中文优先

主要信息使用中文。英文、编号和符号是视觉辅层，不能承载只有英文才能理解的关键内容。

### 5.4 克制的神秘感

神秘感来自黑色空间、矿物纹理、微弱光泽、衬线字和几何秩序，不依赖夸张的星盘、粒子特效或迷信话术。

### 5.5 前台沉浸，后台高效

- 商城前台使用深色画布、较大留白和强图像展示。
- 管理后台使用浅色工作台、紧凑表格和明确边界。
- 两端共享字体、编号、线框、图标和状态组件。

## 6. 色彩系统

### 6.1 基础色

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--color-ink` | `#111111` | 前台背景、主要文字 |
| `--color-paper` | `#F2F1EC` | 前台文字、后台背景 |
| `--color-surface-dark` | `#181818` | 深色卡片和浮层 |
| `--color-surface-light` | `#FFFFFF` | 后台卡片和输入框 |
| `--color-line-dark` | `#3A3A38` | 深色界面分隔线 |
| `--color-line-light` | `#CBCAC3` | 浅色界面分隔线 |
| `--color-muted-dark` | `#B7B6AF` | 深色界面辅助文字 |
| `--color-muted-light` | `#62615D` | 浅色界面辅助文字 |

### 6.2 品牌点色

品牌点色建议使用低饱和紫色 `#9B86C8`，对应紫水晶和夜色。点色占单屏面积不超过约 5%，只用于：

- 当前导航和键盘焦点。
- 主要按钮的悬停或按下状态。
- 少量品牌图形和选中状态。

商品实拍保留天然颜色，是前台最重要的色彩来源。订单状态色由后台配置，但必须同时显示状态文字，不能只依赖颜色传达含义。

### 6.3 色彩禁区

- 不使用大面积荧光渐变。
- 不用纯黑覆盖商品暗部，照片需要保留矿物层次。
- 不把金色作为默认“高级感”方案。
- 不让点色替代错误、警告和成功等语义色。

## 7. 字体与排版

### 7.1 字体角色

| 角色 | 建议字体 | 用法 |
| --- | --- | --- |
| 中文正文与界面 | Noto Sans SC / 思源黑体 | 导航、正文、按钮、表单和表格 |
| 编号与数据 | IBM Plex Mono 或 Geist Mono | 商品编号、规格值、订单号、时间和库存 |
| 编辑式强调 | Noto Serif SC / 思源宋体 | 首页短句、系列标题和少量品牌文案 |
| 品牌字标 | 后续单独设计 | 不直接用装饰字体代替品牌标志 |

字体加载失败时必须有系统字体回退。中文正文不使用等宽字体；等宽字体只用于短标签、英文、数字和代码式信息。

### 7.2 字号建议

| 层级 | 桌面端 | 移动端 | 说明 |
| --- | --- | --- | --- |
| 超大展示标题 | `64–96px` | `40–56px` | 首页首屏，控制在两行内 |
| 页面标题 | `40–56px` | `32–40px` | 分类和商品详情 |
| 区块标题 | `24–32px` | `22–28px` | 商品区、档案区 |
| 卡片标题 | `18–22px` | `17–20px` | 商品名称 |
| 正文 | `16–18px` | `16px` | 行高至少 1.6 |
| 标签与数据 | `12–14px` | `12–13px` | 等宽字体，可适当增加字距 |

英文大写只用于短标签。中文、长句、按钮和错误信息保持正常书写，不使用全角字距模拟英文海报。

## 8. 网格与空间

- 桌面端使用 12 栏网格，内容最大宽度建议 `1440px`，常规内容宽度 `1280px`。
- 平板端使用 8 栏，移动端使用 4 栏。
- 基础间距单位为 `8px`，常用间距为 `8 / 16 / 24 / 32 / 48 / 64 / 96`。
- 前台区块纵向间距较大，允许黑色留白参与构图。
- 后台采用更紧凑的 `8 / 12 / 16 / 24 / 32` 间距。
- 卡片以 1px 边框分隔，不依赖大面积阴影。
- 常规容器圆角使用 `0–4px`；胶囊标签和状态徽标可以使用全圆角。

## 9. 图形、图标与影像

### 9.1 图形语言

优先使用简单、可复用的 SVG：

- 单线圆环、同心圆和珠串序列。
- 四向晶芒、切面菱形和点阵。
- `//`、`→`、`◇`、`○` 等短符号。
- 1px 线框、角标和裁切标记。

同一屏最多使用一到两种装饰语法。装饰图形设置 `aria-hidden="true"`，不进入键盘焦点顺序。

### 9.2 图标

- 使用统一的线性图标库，默认线宽一致。
- 图标必须配合文字或无障碍名称。
- 不混用实心、手绘、拟物和 Emoji 图标。

### 9.3 商品摄影

- 主图以深灰或中性背景为主，使用侧光表现珠体通透度和纹理。
- 保留天然包裹体、色差和细节，不把商品修成完全一致的塑料质感。
- 商品卡片建议使用 `4:5` 比例，详情主图可使用 `1:1` 或 `4:5`。
- 同一商品轮播图包含整体、佩戴或尺寸参照、材质微距和细节瑕疵。
- 照片需要校准颜色；滤镜不能让客户误判材质和颜色。

## 10. 核心组件

### 10.1 导航

- 左侧展示品牌字标，中部为分类和搜索，右侧为登录或客户中心。
- 桌面端可显示短编号或状态文字作为品牌辅层，移动端隐藏纯装饰信息。
- 移动端采用抽屉导航，保留搜索、分类、订单和登录入口。

### 10.2 商品卡片

商品卡片按以下顺序展示：

1. 商品图片。
2. 商品编号和分类标签。
3. 商品名称。
4. 参考价或参考价格区间。
5. “有货”或“已售罄”。

图片悬停可以轻微放大，幅度不超过 `1.02`。售罄不把图片完全灰化，使用明确标签和禁用购买状态即可。

### 10.3 按钮

- 主按钮：纸白底、黑字、硬边框；悬停时使用品牌点色或黑白反转。
- 次按钮：透明底、当前文字色边框。
- 文字按钮：用于低风险导航，不承担关键提交。
- 危险按钮：只在取消订单、删除草稿等场景使用，并需要确认。
- 按钮最小触控尺寸为 `44 × 44px`，加载时保留原宽度。

按钮文案直接使用“立即购买”“提交订单”“确认订单”“取消订单”，不使用抽象的“执行”“启动任务”。

### 10.4 标签与状态

- 标签采用等宽小字、1px 边框和紧凑内边距。
- 状态始终同时展示文字、颜色和可选图标。
- “有货/已售罄”是商品可售状态；“待确认/已确认/已完成/已取消”是订单状态，两者不可混用。
- 参考价旁固定出现“参考价”或相同含义提示。

### 10.5 表单

- 标签置于输入框上方，不只依赖 placeholder。
- 输入框使用清晰边框和高对比焦点环。
- 错误信息紧邻字段，保留用户已填写的有效内容。
- 订单确认页把“最终价格、付款、地址和交付方式需与商家私聊确认”放在提交按钮之前。

### 10.6 表格与后台操作

- 表头固定，数字右对齐，商品名称左对齐，订单号和时间使用等宽字体。
- 主要操作直接显示，低频操作收进菜单。
- 库存总量、已预留数量和可售库存必须在同一区域对照展示。
- 状态流转操作在确认弹窗中说明结果及库存影响。

### 10.7 反馈状态

所有页面和组件必须设计以下状态：

- 首次加载与局部加载。
- 空数据。
- 搜索无结果。
- 网络或服务错误。
- 无权限与登录过期。
- 商品下架、规格停用和售罄。
- 重复提交被拦截。

加载效果使用静态骨架或短促扫描动画，不使用持续闪烁。

## 11. 商城前台页面方向

### 11.1 首页

首页采用“品牌首屏 + 系列索引 + 商品档案网格”的结构：

```text
┌────────────────────────────────────────────────────┐
│ BRAND              分类 / 搜索        登录 / 订单 │
├────────────────────────────────────────────────────┤
│ COLLECTION 01                                    ◇ │
│ 每一串，都是一份独立的矿物档案                      │
│ [浏览全部]                         珠串轨道装饰     │
├────────────────────────────────────────────────────┤
│ 01 水晶系列 │ 02 佛珠系列 │ 03 其他饰品            │
├────────────────────────────────────────────────────┤
│ [商品图]         [商品图]         [商品图]          │
│ CRYSTAL-001      BEADS-004        CRYSTAL-012      │
│ 商品名称          商品名称          商品名称          │
│ 参考价 / 有货     参考价 / 售罄     参考价 / 有货     │
└────────────────────────────────────────────────────┘
```

首页不使用自动轮播大图。首屏只保留一个主要行动入口，商品排序严格遵循后台配置。

### 11.2 分类、搜索与商品列表

- 页面顶部展示分类编号、大标题和商品数量。
- 搜索框保持常规输入体验，装饰标签不冒充筛选器。
- 桌面端每行 3–4 张商品卡片，移动端每行 2 张；极窄屏可降为单列。
- 一期没有组合筛选器，不设计材质、颜色、功效或价格筛选假入口。

### 11.3 商品详情

```text
┌────────────────────────────────────────────────────┐
│ [主图 / 轮播]             CRYSTAL-001 / 有货       │
│                            商品名称                 │
│                            参考价 ¥---              │
│                            [规格选择]               │
│                            [数量 - 1 +]             │
│                            [立即购买]               │
│                            最终价格以私聊确认为准    │
├────────────────────────────────────────────────────┤
│ 材质档案 │ 规格记录 │ 影像记录                     │
└────────────────────────────────────────────────────┘
```

- 桌面端图片与购买区左右分栏，购买区可以在合理范围内吸顶。
- 移动端使用单列布局，并在用户选择有效规格后显示底部固定购买栏。
- 微信二维码不在商品详情公开展示。

### 11.4 登录与注册

- 使用独立、安静的单列表单，不让品牌装饰干扰验证码和密码操作。
- 明确区分登录、注册和找回密码。
- 从立即购买进入时提示“登录后将返回当前商品”，登录成功后恢复商品、规格和数量。

### 11.5 订单确认与成功页

- 订单确认页优先展示商品快照和联系字段，避免做成支付收银台。
- 提交按钮使用“提交订单”，不使用“确认支付”或“立即付款”。
- 成功页把订单编号设计成醒目的档案编号块。
- 商家微信号、二维码和联系说明作为下一步行动区域，只在下单成功页及订单详情展示。

### 11.6 我的订单

- 移动端优先使用订单卡片，桌面端可使用列表。
- 每张订单突出商品摘要、当前状态、参考金额和创建时间。
- 待确认订单显示取消入口；已确认订单提示联系管理员，不展示退款按钮。

## 12. 管理后台页面方向

后台采用“浅色控制台”版本：纸白背景、黑色文字、细边框和等宽数据。装饰只保留在页面标题、空状态和品牌标识中。

### 12.1 框架

- 左侧固定导航：商品、分类、库存、订单、客户、商家配置。
- 顶部显示当前模块、管理员入口和必要的全局反馈。
- 主内容区域优先使用表格、分栏表单和详情抽屉。
- 不设计一期不存在的数据看板、销售额或支付统计。

### 12.2 信息密度

- 前台可用大面积留白，后台每屏应完成一个明确管理任务。
- 编号、库存和时间使用等宽字体，说明文字使用中文黑体。
- 装饰性英文、点阵和轨道图形不得进入数据表格主体。

### 12.3 关键操作

- 上下架、库存调整和订单状态流转必须展示当前状态与操作结果。
- 取消已确认订单时，弹窗要求管理员确认商品能否重新销售，或同步记录库存损耗。
- 状态显示配置只编辑显示名称、颜色和排序，稳定状态代码只读。

## 13. 响应式规则

- 设计基准宽度为 `375px`、`768px`、`1280px` 和 `1440px`。
- 小于 `768px` 时，首页大标题缩小、纯装饰标签隐藏、商品信息改为单列或双列。
- 商品详情移动端先展示图片和名称，再展示规格、数量和立即购买。
- 后台在平板宽度下保留核心操作；宽表格允许局部横向滚动，关键列需要固定。
- 不允许整页产生横向滚动。

## 14. 动效

- 普通过渡时长为 `160–240ms`，使用稳定的 ease-out 曲线。
- 允许轻微的文字揭示、边框扫描和商品图缩放。
- 不使用持续故障闪烁、随机抖动、强视差或自动播放背景视频。
- 支持 `prefers-reduced-motion`，关闭非必要动画。
- 动效不延迟购买、登录和后台操作反馈。

## 15. 无障碍与可用性

- 正文、按钮、表单和状态达到 WCAG AA 对比度要求。
- 所有可交互元素具备明显的键盘焦点，焦点不能只靠颜色变化。
- 触控目标最小为 `44 × 44px`。
- 商品图片提供描述商品本身的替代文本；纯装饰图形对辅助技术隐藏。
- 不用超小字号模拟工业铭牌，关键内容在移动端至少 `16px`。
- 错误、售罄和订单状态同时使用文字表达。
- 页面结构使用正确的标题层级、表单标签、按钮和表格语义。

## 16. 内容语气

品牌文案应当克制、具体、尊重客户判断：

| 推荐 | 避免 |
| --- | --- |
| 天然材质，每件纹理略有差异 | 保证转运、招财或治愈 |
| 商品编号 `CRYSTAL-001` | 能量等级 `MAX 99` |
| 材质档案、规格记录、影像记录 | 作战任务、权限等级、机密档案 |
| 参考价，最终价格以商家确认为准 | 应付金额、支付成功 |
| 添加商家微信并发送订单编号 | 扫码付款 |

一期不实现命理分析，因此界面不展示生肖、八字、星座适配度或推荐结论。

## 17. 实现约束

- 颜色、字体、间距、圆角和动效统一定义为设计 Token，并映射到 Tailwind 配置。
- 优先使用 shadcn/ui 的可访问基础交互，再通过 Token 和组合方式实现品牌视觉。
- 品牌图形使用 SVG 或 CSS，不把重要文字做成图片。
- 前台和后台共享基础组件；商品卡片、库存表格和订单状态等领域组件分别维护。
- 不在页面内散落硬编码状态颜色；订单状态显示配置由 API 返回。
- 商品图片使用响应式尺寸与懒加载，首屏主图需要优先加载并避免布局跳动。

## 18. 设计验收清单

进入开发前，设计稿至少满足：

1. 首页、商品列表、商品详情、登录、订单确认、下单成功和我的订单均有桌面与移动版。
2. 后台登录、商品、库存、订单、客户和商家配置均有核心页面或关键状态说明。
3. 商品卡片和详情页覆盖有货、售罄、下架或规格停用状态。
4. 购买流程覆盖未登录拦截、登录后返回、重复提交和库存不足。
5. 订单覆盖四个固定状态及允许操作，不出现支付、退款或物流状态。
6. 商家微信二维码只出现在下单成功页和订单详情。
7. 所有表单具有默认、焦点、错误、禁用、提交中和成功状态。
8. 设计在 `375px`、`768px`、`1280px` 和 `1440px` 下没有信息遮挡或整页横向滚动。
9. 黑白界面、状态色和点色通过对比度检查，键盘焦点清晰可见。
10. 商品实拍颜色未被品牌滤镜改变，客户能够判断材质和天然差异。
