# 命理饰品商城一期产品需求文档

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v0.1 |
| 当前状态 | 一期需求初稿 |
| 产品形态 | 普通 Web 网站 |
| 业务范围 | 水晶手串、佛珠及相关饰品的展示、库存与订单管理 |

## 2. 项目概述

本项目是一个以水晶手串、佛珠及相关饰品为主要商品的 Web 商城。系统分为面向客户的商城前台和面向运营人员的管理后台，两端共用商品、库存、用户和订单数据。

一期以完成商品展示、登录购买、订单生成及后台运营管理的基础闭环为目标。客户提交订单后，由商家通过微信等私聊方式联系客户，并在线下完成转账及后续交易处理。系统暂不接入微信支付、支付宝等在线支付接口，也暂不实现算命、八字分析或智能推荐功能。

## 3. 一期目标

1. 建立可供客户浏览商品的 Web 商城。
2. 支持客户注册、登录，并在登录后立即购买商品。
3. 支持运营人员在后台维护商品、规格、价格、库存和上下架状态。
4. 支持生成订单，并由运营人员查看订单信息和人工维护订单状态。
5. 前台仅展示商品“有货”或“已售罄”，后台维护真实库存数量。
6. 支持配置商家微信联系方式，引导客户提交订单后与商家私聊完成交易。

## 4. 一期不包含的范围

- 购物车。
- 微信支付、支付宝及其他在线支付接口。
- 自动对账、自动退款及支付回调。
- 物流接口、自动发货及物流轨迹查询。
- 算命、八字分析、生肖分析及智能商品推荐。
- 优惠券、积分、会员等级和复杂营销活动。
- 内容社区、直播、分销和供应商系统。

## 5. 用户角色

### 5.1 商城客户

- 未登录时可以浏览商品列表和商品详情。
- 点击“立即购买”时必须先登录。
- 登录后可以提交订单、查看自己的订单列表和订单详情。
- 可以在订单提交成功后查看商家微信联系方式，并与商家私聊完成后续交易。

### 5.2 后台管理员

- 登录管理后台。
- 管理商品分类、商品、规格、价格、库存和上下架状态。
- 查看用户及订单信息。
- 修改订单状态和填写后台备注。
- 配置订单状态以及商家微信联系方式。

一期可以只设置管理员角色，后续再扩展超级管理员、商品运营、订单客服和只读人员等细分权限。

## 6. 系统组成

### 6.1 商城前台

面向客户使用，采用普通 Web 网站形式，并兼顾电脑和手机浏览器的响应式展示。

### 6.2 管理后台

面向运营和管理人员使用，采用独立的 Web 管理页面。后台账户与商城客户账户相互独立。

### 6.3 统一业务服务

商城前台与管理后台共用统一的商品、库存、用户和订单数据，保证后台上架、下架或调整库存后，商城前台能够获得最新结果。

## 7. 核心业务流程

### 7.1 商品上架流程

1. 管理员登录后台。
2. 新建商品并填写商品基本信息。
3. 上传商品主图和详情图片。
4. 配置商品规格、价格和真实库存数量。
5. 保存为草稿并检查展示内容。
6. 将商品设置为上架状态。
7. 商品在商城前台展示；库存大于 0 时显示“有货”，否则显示“已售罄”。

### 7.2 客户购买流程

1. 客户进入商城并浏览商品。
2. 客户进入商品详情页，选择可用规格。
3. 客户点击“立即购买”。
4. 系统检查登录状态；未登录客户先完成注册或登录。
5. 客户确认商品信息，并填写收货人、联系电话、收货地址及可选备注。
6. 系统再次校验商品上下架状态和可用库存。
7. 客户提交订单，系统生成唯一订单编号并扣减相应库存。
8. 下单成功页展示商家微信号、微信二维码和联系说明。
9. 商家通过微信等方式联系客户，并在线下完成转账及后续处理。
10. 管理员在后台修改订单状态。

### 7.3 订单取消与库存恢复

- 未完成的订单被取消时，系统恢复对应商品规格的库存。
- 已完成订单不允许由客户直接取消。
- 后台管理员可以根据实际沟通结果修改订单状态。
- 同一次取消操作不得重复恢复库存。

## 8. 商城前台需求

### 8.1 首页

- 展示商城名称、品牌信息和主要导航。
- 展示推荐商品或最新上架商品。
- 提供商品分类入口。
- 展示商家服务说明或联系入口。

### 8.2 商品列表

- 按分类展示已上架商品。
- 支持按商品名称搜索。
- 每个商品卡片展示主图、名称、价格和库存状态。
- 只展示“有货”或“已售罄”，不展示具体库存数量。
- 已售罄商品允许查看详情，但“立即购买”按钮不可用。

### 8.3 商品详情

- 商品名称。
- 商品主图及轮播图。
- 商品价格。
- 商品介绍和详情内容。
- 可选规格，例如珠径、手围、材质或颜色。
- 当前规格的“有货”或“已售罄”状态。
- 购买数量，默认数量为 1，且不得超过后台可用库存。
- “立即购买”按钮，不提供“加入购物车”按钮。
- 商家联系及交易方式说明。

### 8.4 注册与登录

- 一期采用手机号和密码注册、登录。
- 注册时至少填写手机号、密码和确认密码。
- 手机号在系统内唯一。
- 密码不得明文保存。
- 登录成功后，客户应返回登录前准备购买的商品或订单确认页。
- 支持安全退出登录。
- 短信验证码登录及找回密码短信暂不属于一期范围；可先由客服人工协助处理忘记密码问题。

### 8.5 确认订单

- 展示商品名称、图片、所选规格、单价、数量和订单金额。
- 填写收货人姓名、联系电话和收货地址。
- 支持填写可选的微信号和订单备注。
- 提交前明确提示：平台暂不提供在线支付，提交后请通过微信与商家联系。
- 防止因重复点击产生重复订单。

### 8.6 下单成功

- 展示下单成功提示和订单编号。
- 展示商家微信号、微信二维码及联系文案。
- 提供“查看订单”和“继续浏览商品”入口。
- 不展示系统已收款等容易引起误解的描述。

### 8.7 我的订单

- 仅登录客户可访问。
- 客户只能查看自己创建的订单。
- 列表展示订单编号、商品摘要、订单金额、订单状态和下单时间。
- 订单详情展示下单时保存的商品快照、联系人、地址、备注和商家联系方式。

## 9. 管理后台需求

### 9.1 管理员登录

- 管理员使用独立后台入口登录。
- 后台登录失败时给出明确但不泄露账户信息的提示。
- 未登录访问后台页面时跳转到后台登录页。

### 9.2 商品分类管理

- 新增、编辑、启用和停用分类。
- 设置分类名称、图片和排序。
- 已被商品使用的分类不应直接物理删除。

### 9.3 商品管理

- 新增、编辑、复制和查看商品。
- 保存草稿、上架和下架商品。
- 配置商品名称、分类、商品编号、主图、轮播图、详情、价格和排序。
- 支持设置多个商品规格，每个规格独立维护价格和库存。
- 商品下架后不再允许客户创建新订单，但不影响历史订单查看。

### 9.4 库存管理

- 后台展示每个商品规格的真实库存数量。
- 支持增加、减少和修正库存。
- 库存不得小于 0。
- 保存库存变更记录，包括变更前数量、变更数量、变更后数量、原因、操作人和时间。
- 前台不提供真实库存数值，只根据可用库存显示“有货”或“已售罄”。

### 9.5 订单管理

- 按订单编号、客户手机号、商品名称和订单状态搜索订单。
- 查看订单基本信息、商品快照、客户信息、收货信息和备注。
- 修改订单状态。
- 填写仅管理员可见的后台备注。
- 记录订单状态变更前后的值、操作人和操作时间。
- 不在系统内处理支付凭证、支付回调和物流轨迹。

### 9.6 订单状态配置

订单只保留一个当前状态字段，不拆分支付状态、发货状态和售后状态。

后台支持配置：

- 状态名称。
- 展示颜色。
- 排序。
- 是否启用。

建议一期预置以下状态：

| 状态 | 用途 |
| --- | --- |
| 新订单 | 客户刚提交，等待商家处理 |
| 跟进中 | 商家已通过微信或其他方式联系客户 |
| 已完成 | 线下交易及后续处理已完成 |
| 已取消 | 订单不再继续，库存已恢复 |

状态名称允许后台调整，但已被历史订单使用的状态不应直接删除，可以停用。

### 9.7 用户管理

- 查看客户手机号、注册时间和最近登录时间。
- 查看客户订单记录。
- 支持启用或停用账户。
- 默认不允许管理员查看客户密码。

### 9.8 商家联系配置

- 配置商家微信号。
- 上传微信二维码。
- 配置下单成功后的联系说明。
- 配置客服工作时间等补充信息。
- 配置更新后应用于新的前台展示，历史订单仍保留必要的联系信息快照。

## 10. 核心数据要求

### 10.1 商品

- 商品 ID。
- 商品编号。
- 商品名称。
- 商品分类。
- 主图、轮播图和详情内容。
- 商品状态：草稿、上架、下架。
- 排序值。
- 创建人、创建时间和更新时间。

### 10.2 商品规格

- 规格 ID。
- 所属商品 ID。
- 规格名称及规格值。
- 售价。
- 真实库存数量。
- 规格状态。

### 10.3 客户

- 客户 ID。
- 手机号。
- 加密后的密码。
- 账户状态。
- 注册时间和最近登录时间。

### 10.4 订单

- 订单 ID 和唯一订单编号。
- 客户 ID。
- 商品及规格快照。
- 下单单价、数量和订单总金额。
- 收货人、联系电话和收货地址。
- 可选微信号和客户备注。
- 当前订单状态。
- 后台备注。
- 创建时间和更新时间。

商品快照用于保证商品名称、图片、规格或价格被后台修改后，历史订单仍展示下单时的真实信息。

## 11. 关键业务规则

1. 客户可以免登录浏览商品，但必须登录后才能提交订单。
2. 一期只有“立即购买”，不提供购物车。
3. 只有已上架且所选规格库存大于 0 的商品可以购买。
4. 前台不显示真实库存数量。
5. 提交订单时必须再次校验库存，避免并发下单导致超卖。
6. 订单创建成功后扣减库存；取消订单时只恢复一次库存。
7. 订单不包含在线支付结果，管理员根据线下沟通情况人工维护状态。
8. 历史订单必须使用商品快照，不随商品后续编辑而改变。
9. 客户只能查看自己的订单，管理员可以查看全部订单。
10. 关键后台操作应保留操作记录。

## 12. 非功能要求

### 12.1 安全性

- 全站使用 HTTPS 部署。
- 密码使用可靠的单向哈希算法保存。
- 登录接口需要具备基础的防暴力尝试措施。
- 后台接口必须验证管理员身份和权限。
- 对输入内容进行校验，防止常见注入和跨站脚本风险。
- 不在日志中记录密码等敏感信息。

### 12.2 易用性

- 前台适配常见电脑和手机浏览器。
- 购买流程尽量保持单页或少步骤完成。
- 上下架、库存和订单状态使用清晰的视觉标识。
- 表单校验信息明确，并保留客户已经填写的有效内容。

### 12.3 数据一致性

- 订单创建和库存扣减应作为不可分割的业务操作。
- 订单取消和库存恢复应避免重复执行。
- 后台库存修改和订单状态修改应记录审计信息。

## 13. 一期验收标准

1. 未登录客户能够浏览已上架商品，但点击“立即购买”会被要求登录。
2. 客户可以使用手机号和密码完成注册、登录和退出。
3. 登录客户能够选择有库存的商品规格并成功提交订单。
4. 商品库存为 0 时，前台显示“已售罄”并禁止提交订单。
5. 前台任何页面均不展示具体库存数量。
6. 下单成功后能够看到订单编号、商家微信号、二维码及联系说明。
7. 客户能够在“我的订单”中查看自己的订单和当前状态，且不能查看其他客户订单。
8. 管理员能够新增商品、配置规格与库存，并完成上下架。
9. 管理员能够搜索、查看订单，并修改唯一的订单状态字段。
10. 管理员能够配置订单状态和商家微信联系方式。
11. 订单创建后库存正确扣减，订单取消后库存只恢复一次。
12. 修改商品名称、图片、规格或价格后，历史订单中的商品快照保持不变。

## 14. 后续迭代方向

- 短信验证码登录和自助找回密码。
- 微信登录、微信支付及支付回调。
- 自动关闭长期未处理订单及库存释放策略。
- 物流信息和售后管理。
- 命理标签、八字分析和商品推荐。
- 收藏、购物车、优惠券、会员和营销功能。
- 更细粒度的后台角色权限和经营数据看板。
